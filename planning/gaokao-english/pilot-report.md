# 七天试点报告（pilot-report）

> 状态：**试点未开始**（真人试用未执行）。本文档先固化记录协议、第 7 天抽取规则、阻塞判定与 P09 逐条验收口径；试用启动后按日回填，**不伪造任何试用数据**。单人试用不能推断稳定提分；兴趣/意愿改善只代表该用户当期反馈。

## 一、记录协议（每日）

每天只保存以下汇总字段（不保存个人原始作答全文、不保存可识别身份信息）：

| 字段 | 说明 |
| --- | --- |
| 日期 | 自然日 D1–D7 |
| 任务完成 | 当日计划单元是否完成（完成/部分/未开始） |
| 实际时长 | 分钟（以应用会话记录或自报） |
| 独立首次表现 | 首次作答 independent-pass / needs-help 分布（设置→数据页可查） |
| 主观难度 | 1–5（1 太易 5 太难）+ 一句话 |
| 是否愿意再练 | 愿意 / 一般 / 不愿意 |

首次独立完成一个基础单元时，需要帮助的操作逐条记录：点哪里、看什么提示、卡住多久。不以开发者演示代替用户试用。

## 二、第 7 天平行题抽取（已自动化）

规则：从未曝光的**同 family（同题型族）**、**同技能（skillIds）**、**同层级（level G0/G1/G2）**题中抽取，确定性、无随机（每技能×层级默认取 3 题候补），报告可复现。

如实口径（评审 R5）：运行时 slot.assistance 恒从空起步、提示按需累计，**不存在 item/family 级静态辅助配置**；辅助「可用性」由题型/栏目/资源决定（规则提示=非写作、听力原文=有 transcript 资源、范文=写作）。内容校验未强制同 family 的结构一致，故「辅助条件一致」由**施测程序**保证：第 7 天平行题必须在**无提示的新会话**中作答（fresh slot 天然 assistance=[]），不得沿用旧会话或先看提示。多技能题在建议 JSON 的 alsoCovers 字段标注，避免一题被当两技能计。

工具：直接运行 "npm run pilot:day7 -- <备份导出.json> [profileId]"（内部 tsx scripts/pilot-day7.ts）。读取应用「设置 → 备份与恢复」导出的 JSON，输出每技能×层级的未曝光平行题建议与缺口清单（区分「该技能从未练过」与「练过但无候选」两态，均如实标注，不换题充数）；旧 schema 备份（曝光行缺 profileId）会被拒绝并提示重新导出。纯函数与用例：src/services/pilot-day7.ts、tests/unit/pilot-day7.spec.ts（5 项）。

## 三、阻塞问题判定（修复并复测后才可发布）

以下任一出现即阻塞：数据丢失（重开丢会话/作答/草稿）、答案错判（正确被判错或反向）、无法退出/恢复（会话卡死无出路）、音频阻断（听力无法播放且无降级路径）。其余问题记为一般问题，列入待办不阻塞 v0.1。
